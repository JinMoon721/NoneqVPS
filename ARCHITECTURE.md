# Architecture for the VPS with ML Solver

This package is generated by Jin Moon at Apr 2, 2026

## 1. Top-level idea

The codebase has five conceptual layers:

1. **Configuration**
   - global simulation and training constants
   - file: `VPS_pkg/config.py`

2. **MD Simulation / trajectory generation**
   - ASE calculator
   - BAOAB Langevin integrator
   - utilities for distance, path saving, velocity-flipped reverse paths
   - files: `VPS_pkg/physics/*.py`

3. **Model**
   - feature construction from `(positions, tau, cell)`
   - committor network
   - spatial gradient to Doob force
   - files: `VPS_pkg/model/*.py`

4. **Data**
   - dataclass definitions
   - metadata I/O
   - loading merged `.npz` samples
   - collating a list of samples into a batch tensor package
   - files: `VPS_pkg/data/*.py`

5. **Loss + training**
   - BAOAB coefficients
   - OM-action / variational objective
   - batch loss
   - checkpointing and epoch loop
   - files: `VPS_pkg/loss/*.py`, `VPS_pkg/train/*.py`

## 3. Main dataclasses

## `ReactiveSample`
Defined in `VPS_pkg/data/types.py`.

This is the standard in-memory representation of one stitched reactive trajectory sample.

```python
@dataclass
class ReactiveSample:
    pos_fwd: np.ndarray      # (sf+1, N, 3)
    xi_fwd: np.ndarray       # (sf,   N, 3)
    pos_bwd: np.ndarray      # (sb+1, N, 3)
    xi_bwd: np.ndarray       # (sb,   N, 3)
    cell: np.ndarray         # (3, 3)
    steps_forward: int
    steps_backward: int
    masses: np.ndarray | None = None
```

## `BatchSamples`
Defined in `VPS_pkg/data/types.py`.

This is the collated tensor batch used by the batch loss.

```python
@dataclass
class BatchSamples:
    steps_forward: torch.Tensor   # (B,)
    steps_backward: torch.Tensor  # (B,)
    total_steps: int
    positions: torch.Tensor       # (B, T+2, N, 3)
    noises: torch.Tensor          # (B, T,   N, 3)
    cell: torch.Tensor            # (B, T+2, 3, 3)
```

---

## 4. Tensor-shape conventions

These are the conventions used everywhere.

- `B` = batch size
- `N` = number of atoms
- `T` = total number of BAOAB noise steps in the stitched path
- `sf` = forward steps
- `sb` = backward steps
- `T = sf + sb`

Stitched objects use:

- positions: `(T+2, N, 3)` for one sample
- noises: `(T, N, 3)` for one sample
- in batch form:
  - positions: `(B, T+2, N, 3)`
  - noises: `(B, T, N, 3)`

## B. Model creation and direct feature inference

```python
from VPS_pkg.model.committor_net import CommittorNet

model = CommittorNet(tempK=config.tempK, in_dim=2, hidden_dim=64)
q, logq = model.forward_from_features(features)
```

For full trajectory input:

```python
q, logq = model(positions, tau, cell)
q, logq, doob = model.doob(positions, tau, cell)
```

Expected shapes:

- `positions`: `(B, T, N, 3)`
- `tau`: `(B, T)` or `(B, T, 1)`
- `cell`: `(B, T, 3, 3)`

3. slices them into mini-batches,
4. collates each mini-batch,
5. runs one optimizer step per mini-batch.

## 7. Recommended rule for future changes

When adding new code, decide first which layer it belongs to.

- new physics force field → `physics/`
- new neural feature or network → `model/`
- new sample format or file loading → `data/`
- new objective / estimator → `loss/`
- new optimizer schedule or epoch logic → `train/`

Do not mix these in one file unless the code is trivial.

## 8. Minimal end-to-end usage example

```python
from VPS_pkg.config import default_config
from VPS_pkg.model.committor_net import CommittorNet
from VPS_pkg.train.trainer import train_on_one_npz

import torch

config = default_config()
device = "cpu"

model = CommittorNet(tempK=config.tempK, in_dim=2, hidden_dim=64).to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=1e-4)

avg_loss = train_on_one_npz(
    path="./merged/train0.npz",
    model=model,
    optimizer=optimizer,
    config=config,
    device=device,
    batch_size=4,
)

print("avg_loss:", avg_loss)
```
